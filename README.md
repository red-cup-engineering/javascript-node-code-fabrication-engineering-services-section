The Javascript Node Code Fabrication Services Section maintains knowledge and practices for this service domain.

Its material is organized by artifact role under `content/`; specialized
subdomains continue under `services/`.
## Receive the original reviewed Specification/Architecture as Code source

The existing JavaScript source-to-TypeScript/runtime fabricator is now exercised
against the **actual original** Specification Engineering maker selected at
its immutable mainline source revision. Native CI installs both the Code
package and a separate original Specification source checkout, then performs:

\`Requirement → independently interpreted Specification → author-reviewed
Architecture candidate → source-bound Code schema and immutable JavaScript
module → original source-revision impact\`.

The original source modules, not copied local data formats, derive the
Specification and Architecture. The Code maker's existing
\`renderJsonSchemaModule\` produces the runnable ESM carrier. A native test
imports that ESM and checks the exact original design, recursively immutable
constraints, intentionally untraced beneficiary condition, changed-model
regeneration, stable replay, and refusal of stale Requirement or forged
architectural decision source. These are executable source/product assays,
not a new code-generation engine or a parallel WorkCell store.

The review still supplies actual architectural design choices; the generator
does not invent them or assume the designer's authority. A generated schema
carrier is neither an implemented customer workflow nor proof that code
performs its source contract. Independent Proof, Work authorization, code
effects, installed runtime behavior and beneficiary settlement remain
separate receivers. The native test suite enforces this distinction rather
than claiming that schema parsing settles the original Group Requirement.

Stage-Proof review of the exact source/design, admitted Work, native maker effects, host installation, actual beneficiary acceptance and settlement remain separately owned and unreceived. These automated tests are necessary **source-to-consumer qualification**, not the Engineering closure's final result.

## Native Requirement/Design → executable Code contract, test and repair receiving

The original Code maker now exports
`./project-engineering-design-code`. This operation consumes an **original
Specification-owned `readEngineeringCodeWork` result**: the Requirement,
Specification, Architecture, high-level and low-level Design source cut
is re-received by the owning generator, and each Code target retains its
original HLD component owner, module/export pair, SHA-256 source bytes,
Requirement-cell/Specification-clause/Architecture-model trace and
unreceived normative obligations. No second Design reader, requirements
registry or model-generated implementation semantics is introduced.

For a source-present readout and externally supplied assay cases that cover
every original target Requirement cell, the Code maker emits source-addressed
**executable ESM adapters** and native `node:test` test files, grouped by
the actual source component owner. Adapters use the existing SignCell runtime
schema types to check the inputs and outputs of the original source
implementation, check the source SHA-256 *before loading the module*, and
import the exact original export name. The generated cases check the
supplier-independent expected output or thrown error; a failed case is a
real disagreement rather than an asserted coverage score. The projection
is deterministic for the same source/Design and test evidence and refuses
stale code views, changed Design standing, missing per-cell cases or
unbounded carriers before writing anything.

The original Code CI now uses the latest **independently built, clean-installed
and Sigstore/SLSA attested** Specification source cut
`db52af5115ce9cc12e027d3ec23c42fe5a2a1aa2` with exact qualified
tarball SHA-256
`4f8ec8696390f40cde192447a9f48bcd571f6e53a4a6d09ae4d2fc240c4b74a2`.
The actual original HLD/LLD reader supplies the tests' Code-work readout.
One native run generates two real operation adapters, executes four
source-traced acceptance cases, proves that a changed source is refused,
requalifies the changed source and observes an output disagreement, then
repairs the implementation and re-runs the **same cases**. It repeats
through the separately packed/installed public Code maker export, not only
through local test imports.

These are **usable candidate Code artifacts and independent runnable tests**.
They do not grant an original WorkCell execution authority; the source bytes
and model may still be untrusted. This library never executes candidate code;
the native CI uses only known trusted fixture implementations. A serving
host must supply a verified isolated executor before model-authored source
can run, and independent Engineering Stage Proof, SignCell/SignChain issuer,
repository effect, buyer receiving and settlement remain separate duties.
The function expressly returns `semanticProof:"unreceived"`,
`executableWork:false`, `codeApplied:false`, and
`beneficiaryReceived:false`; passing functional tests cannot change them.
